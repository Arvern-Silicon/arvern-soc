# demo_arvern_logo — the aRVern logo on Belenos

The aRVern logo on the RGB panel, in a loop of six scenes, each showing a feature of the
Belenos graphic controller. It uses the Belenos driver library (`arvern-belenos/sw`), the
ACLINT driver and the board support (`../../bsp`).

The display is 480 × 272 at 8 bpp, the size of the panel: two frames fill the VRAM back to
back (F0 at pixel address 0, F1 at 130560), and the 256-entry LUT gives every colour of the logo its own
entry.

| Scene | LEDs | What happens | Belenos feature |
|---|---|---|---|
| 1 paint | 1 | the background gradient, then the logo one colour layer at a time, the wordmark typed in, the subtitle | GPU fills (one per run of pixels); the text as 2 bpp coverage bitmaps expanded by the GPU (EXPAND, 0 transparent) from a copy in the spare VRAM above the two frames |
| 2 power-up | 2 | light pulses run along the circuit traces toward the RV mark | LUT animation: 24 entries rewritten per frame, the VRAM untouched |
| 3 themes | 3 | fade to black, the dark logo fades in, crossfade back to the light one | double-buffered palettes: each palette is built in the LUT bank the refresh is not showing, then the banks swap at a frame start |
| 4 spin | 4 | the screen mirrors and turns upside down | scan orders (`DISP_CFG` swaps), nothing redrawn |
| 5 sprites | 5 | small logos bounce over the gradient, plus a cyan "hologram" | GPU copies with a transparent colour from an off-screen sprite sheet in F1; an XOR raster-operation copy that erases itself. With the palette remap (`GPU_REMAP_EN`) the hologram is the same sheet through a table T[i] = i \| 0x80 (`REMAP SRC`), and each logo casts a translucent shadow: the sheet copied 6 pixels down and right with `REMAP DST`, the gradient under its shape 20 bands darker |
| 6 credits | 6 | the aRVern core page, then the Belenos page, scroll in from below; the title screen follows | moving the refresh frame pointer one line per frame, no copy; between pages a full-frame GPU copy moves F1 into F0, so the next page can be drawn in F1 |

**KEY[1]** skips to the next scene; **SW[0]** holds the current one.
On the HDMI build, holding **KEY[1]** for a second also restarts the HDMI link; the
link restarts on its own when a monitor comes back or selects this input
([`../../lib/demo_kit/README.md`](../../lib/demo_kit/README.md)).

The music ([`score.py`](score.py)) is one piece in E with a section per scene: the pad
and a slow arpeggio (paint), the arpeggio in sixteenths with bass and drums (power-up),
the theme with the whole band (themes), a driving variation (spin), a playful staccato
tune (sprites), the theme again on a soft sine (credits).

## Where the pictures come from

`logo_data.h` is generated by [`tools/logo2c.py`](tools/logo2c.py) from the logo SVGs in
`arvern/doc/img/` and is committed, so a normal build needs neither Inkscape nor Python:

- the logo (200 × 140) and a small copy for the sprites (64 × 45) are rendered without
  antialiasing, every SVG path recoloured with an ID colour, so each pixel maps back to the
  path that painted it; each colour becomes a LUT entry, each circuit trace its own entry
  (ordered from the outermost trace to the RV mark), and the image a list of horizontal
  runs grouped by colour, three bytes each;
- the dark theme uses the same pixels with the colours of `aRVern_dark.svg`, so a theme
  change is a palette change;
- the "aRVern" wordmark (from `aRVern_light_label.svg`) and the text lines (IBM Plex Sans,
  see `THIRD_PARTY.md`) are 2-bit antialiased bitmaps.

Regenerate after changing a logo SVG or a text line (`TEXTS` in the script); `PREVIEW=dir`
also writes PNG previews of what the firmware will draw:

```
make logo [PREVIEW=/tmp/logo]
```

## Build and run

```
make            # demo_arvern_logo.elf / .ihex
make run        # load over the JTAG DTM (see the Makefile for UART / I2C)
```

or build it into a bitstream: `synthesis/gowin/0_create_bitstream.sh demo_arvern_logo`.

The board-level simulation builds the firmware with `-DSIMULATION`: every scene is cut to
a few frames and the loop runs once, then the LEDs show `0xA5`. The panel image is saved
after every frame as `frame_log/fb_<n>.png` (about 90 frames, a few minutes under Verilator):

```
cd ../../../sim/rtl_sim/run
SIMULATION_DEFINES="-D NO_TIMEOUT" ./run demo_arvern_logo -nodump
```
